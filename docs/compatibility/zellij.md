# Zellij compatibility research matrix

Snapshot: 2026-08-03. Zellij is Noren's first-class compatibility target, but
Noren is not intended to replace it. When a Zellij terminal pane is focused,
preserving child input takes priority over Noren shortcuts
([README](../../README.md),
[project principles](../project-principles.md)). This document turns the scope
in [Issue #4](https://github.com/ta-061/noren/issues/4) into future executable
tests. It does not report a Noren runtime result.

Noren remains in Discovery with no terminal application or Preview build.
Therefore, all current rows are **Planned**. Upstream source evidence explains
what the pinned Zellij fixture does; it is kept separate from Noren state,
unknowns, and the conformance tests that could eventually produce release
evidence. The [discovery plan](../research/discovery-plan.md) and
[design process](../coordination/design-process.md) remain the gates for
requirements, independent review, and implementation.

## State legend

The `Noren state` column uses only this vocabulary. A state describes Noren,
never Zellij.

| State | Meaning |
| --- | --- |
| Not planned | A comparison candidate with no accepted Noren delivery commitment. |
| Planned | Product intent exists, but no runtime evidence exists. |
| Experimental | A bounded experiment exists; it is not a product feature. |
| Partial | Some accepted behavior exists, but the row's pass criteria are not all met. |
| Supported | The behavior is implemented within a documented support boundary. |
| Tested | The supported behavior has current release evidence on every named target environment. |

## Versioned upstream fixture

The upstream baseline is Zellij
[v0.44.3](https://github.com/zellij-org/zellij/releases/tag/v0.44.3), published
2026-05-13 from commit
[`55a2121`](https://github.com/zellij-org/zellij/tree/55a2121b73dce4be624cda425a960e893000777c).
Future runs must acquire an official release artifact, verify its accompanying
release checksum, and record `zellij --version` before testing. Mutable User
Guide pages are identified as unversioned context where used; fixture-specific
source and default-keymap statements cite the v0.44.3 source or changelog at
that commit.

The default-keymap fixture is the bundled v0.44.3
[`default.kdl`](https://github.com/zellij-org/zellij/blob/55a2121b73dce4be624cda425a960e893000777c/zellij-utils/assets/config/default.kdl#L1-L225).
The upstream Unlock-First fixture is generated by v0.44.3's
[`unlock_first_keybinds`](https://github.com/zellij-org/zellij/blob/55a2121b73dce4be624cda425a960e893000777c/default-plugins/configuration/src/presets.rs#L1-L210).
The preset screen initializes its primary modifier to `Ctrl` and secondary
modifier to `Alt` ([pinned selector defaults](https://github.com/zellij-org/zellij/blob/55a2121b73dce4be624cda425a960e893000777c/default-plugins/configuration/src/presets_screen.rs#L20-L28)).
The following hashes cover the exact UTF-8 returned by that pinned generator,
including its leading LF and lack of a final LF. Alternative arguments are
test fixtures, not upstream defaults or Noren binding decisions.

The following is the exact future reproduction harness. It invokes the pinned
Rust generator, writes its return value with `print!` rather than `println!`,
and verifies the leading `0a` byte and final `7d` byte before counting and
hashing. The expected byte counts and SHA-256 hashes are embedded in the
harness manifest below and mirror the table above. Every step fails closed: a
missing tool, a non-absolute or unreadable source path, an unresolved or
mismatched commit or tag, a failed `git status` inspection, a dirty tree, a
failed compile, a missing binary, an empty or boundary-invalid fixture, or any
byte-count or hash mismatch aborts the run with a diagnostic and a nonzero
exit before any fixture can be archived. It has not been executed in this
docs-only branch; a future evidence run must supply a clean checkout at the
recorded commit and a pinned Rust toolchain, then archive the command output
and toolchain version.

```sh
set -eu
export LC_ALL=C

fail() {
  printf 'fixture harness: %s\n' "$1" >&2
  exit 1
}

: "${ZELLIJ_SOURCE:?export ZELLIJ_SOURCE=/absolute/path/to/zellij-v0.44.3}"
export ZELLIJ_SOURCE
case "$ZELLIJ_SOURCE" in
  /*) ;;
  *) fail "ZELLIJ_SOURCE is not an absolute path: $ZELLIJ_SOURCE" ;;
esac
[ -d "$ZELLIJ_SOURCE" ] || fail "ZELLIJ_SOURCE is not a directory"
expected_commit=55a2121b73dce4be624cda425a960e893000777c
expected_tag=v0.44.3

for required_tool in git rustc mktemp od tail wc shasum awk
do
  command -v "$required_tool" >/dev/null 2>&1 || \
    fail "missing required tool: $required_tool"
done

fixture_dir=$(mktemp -d)
cleanup() {
  cleanup_status=$?
  trap - 0 1 2 15
  for cleanup_file in \
    "$fixture_dir/render-unlock-first" \
    "$fixture_dir/source-status" \
    "$fixture_dir/boundary.hex" \
    "$fixture_dir/last-byte" \
    "$fixture_dir/count.txt" \
    "$fixture_dir/sha.txt" \
    "$fixture_dir/Z-UF-CTRL-ALT.kdl" \
    "$fixture_dir/Z-UF-ALT-CTRL.kdl" \
    "$fixture_dir/Z-UF-CTRL-SHIFT-ALT.kdl"
  do
    if [ -e "$cleanup_file" ] && ! rm -f "$cleanup_file"
    then
      cleanup_status=1
    fi
  done
  if [ -d "$fixture_dir" ] && ! rmdir "$fixture_dir"
  then
    cleanup_status=1
  fi
  exit "$cleanup_status"
}
trap cleanup 0
trap 'exit 1' 1 2 15

actual_commit=$(git -C "$ZELLIJ_SOURCE" rev-parse --verify HEAD) || \
  fail 'cannot resolve source HEAD'
[ "$actual_commit" = "$expected_commit" ] || \
  fail "source commit mismatch: $actual_commit"
actual_tag=$(git -C "$ZELLIJ_SOURCE" describe --tags --exact-match HEAD) || \
  fail 'source HEAD is not an exact tag'
[ "$actual_tag" = "$expected_tag" ] || \
  fail "source tag mismatch: $actual_tag"
: >"$fixture_dir/source-status" || fail 'cannot create source-status sentinel'
if ! git -C "$ZELLIJ_SOURCE" status --porcelain --untracked-files=normal \
  >"$fixture_dir/source-status"
then
  fail 'cannot inspect source cleanliness'
fi
[ -e "$fixture_dir/source-status" ] || fail 'source-status output vanished'
[ ! -s "$fixture_dir/source-status" ] || fail 'source tree is dirty'

git --version
rustc --version
if ! rustc --edition=2021 -o "$fixture_dir/render-unlock-first" - <<'RS'
mod presets {
    include!(concat!(
        env!("ZELLIJ_SOURCE"),
        "/default-plugins/configuration/src/presets.rs"
    ));
}

fn main() {
    let args: Vec<String> = std::env::args().collect();
    assert_eq!(args.len(), 3, "primary and secondary modifier required");
    print!(
        "{}",
        presets::unlock_first_keybinds(args[1].clone(), args[2].clone())
    );
}
RS
then
  fail 'generator compilation failed'
fi
[ -x "$fixture_dir/render-unlock-first" ] || \
  fail 'generator binary was not produced'

fixture_count=0
while IFS='|' read -r fixture_id primary secondary expected_count expected_sha256
do
  fixture_file="$fixture_dir/$fixture_id.kdl"
  "$fixture_dir/render-unlock-first" "$primary" "$secondary" \
    >"$fixture_file" || fail "generation failed: $fixture_id"
  [ -s "$fixture_file" ] || fail "empty fixture generated: $fixture_id"

  od -An -tx1 -N1 "$fixture_file" >"$fixture_dir/boundary.hex" || \
    fail "cannot read first byte: $fixture_id"
  first_hex=$(awk '{gsub(/[[:space:]]/, ""); printf "%s", $0}' \
    "$fixture_dir/boundary.hex") || fail "cannot parse first byte: $fixture_id"
  tail -c 1 "$fixture_file" >"$fixture_dir/last-byte" || \
    fail "cannot read last byte: $fixture_id"
  od -An -tx1 -N1 "$fixture_dir/last-byte" >"$fixture_dir/boundary.hex" || \
    fail "cannot encode last byte: $fixture_id"
  last_hex=$(awk '{gsub(/[[:space:]]/, ""); printf "%s", $0}' \
    "$fixture_dir/boundary.hex") || fail "cannot parse last byte: $fixture_id"
  [ "$first_hex" = 0a ] || fail "missing leading LF: $fixture_id"
  [ "$last_hex" = 7d ] || fail "unexpected final byte: $fixture_id"

  wc -c <"$fixture_file" >"$fixture_dir/count.txt" || \
    fail "cannot count fixture: $fixture_id"
  byte_count=$(awk 'NR == 1 {print $1} END {if (NR != 1) exit 1}' \
    "$fixture_dir/count.txt") || fail "cannot parse count: $fixture_id"
  shasum -a 256 "$fixture_file" >"$fixture_dir/sha.txt" || \
    fail "cannot hash fixture: $fixture_id"
  sha256=$(awk 'NR == 1 {print $1} END {if (NR != 1) exit 1}' \
    "$fixture_dir/sha.txt") || fail "cannot parse hash: $fixture_id"
  [ "$byte_count" = "$expected_count" ] || \
    fail "byte-count mismatch: $fixture_id"
  [ "$sha256" = "$expected_sha256" ] || \
    fail "SHA-256 mismatch: $fixture_id"

  printf '%s\t%s\t%s\t%s/%s\n' \
    "$fixture_id" "$byte_count" "$sha256" "$first_hex" "$last_hex"
  fixture_count=$((fixture_count + 1))
done <<'FIXTURES'
Z-UF-CTRL-ALT|Ctrl|Alt|8268|7592052cfd068c29b222d6334fb4e4e59b1a0d29f9757f8548235d22e6898f4a
Z-UF-ALT-CTRL|Alt|Ctrl|8284|2768630827f7eace331ed8fc6f2b7be4ce8538aa4b3c0e4242054f655040195e
Z-UF-CTRL-SHIFT-ALT|Ctrl Shift|Alt|8286|4d7ca6ad9ad16a72da44d8a04c8084ea7fbf8b5ebb6768396227cc0ca8d38ac2
FIXTURES
[ "$fixture_count" -eq 3 ] || fail 'fixture manifest count mismatch'
printf 'fixture harness: all %s fixtures verified\n' "$fixture_count"
```

Future tests must regenerate and hash each fixture before use, run with
isolated config/cache/data directories, and archive the effective KDL. A hash
mismatch blocks comparison. A user's custom configuration can replace any
default, so a result for these fixtures is not a claim about every Zellij
configuration. The multi-modifier alternative also requires its host keyboard
protocol to be captured; its presence here is not a KKP support claim.

## Future target environments and evidence ownership

These aliases name future targets; no Noren build or fixture exists today:

- `Z-MAC`: a future Noren release candidate on macOS Apple Silicon, with both
  ANSI-US and Japanese input-source layouts, native Japanese IME, and the
  Preview-supported OS version pinned in the release record.
- `Z-WAYLAND`: the same candidate on Linux x86_64 Wayland with a recorded
  compositor plus an IBus or Fcitx5 Japanese IME.
- `Z-X11`: the same candidate on Linux x86_64 X11 with recorded window manager,
  XKB layout, clipboard provider, and IME.
- `Z-LOCAL`: `Z-MAC`, `Z-WAYLAND`, and `Z-X11` using local PTYs.
- `Z-SSH`: each local client connected through OpenSSH to an isolated Linux
  x86_64 VM running the pinned Zellij artifact; clean-network and `tc netem`
  profiles are both recorded.
- `Z-PROTO`: `Z-LOCAL` with a PTY-boundary byte recorder and raw inner helper;
  `$TERM`, `$COLORTERM`, terminfo identity, keyboard layout, mode transitions,
  and exact input/output bytes are captured without secrets.
- `Z-LOAD`: `Z-LOCAL` and `Z-SSH` with deterministic bounded output, latency,
  memory, and resize instrumentation.

Keyboard tests use a two-layer `Z-2L` oracle. At the outer boundary, every event
designated for child forwarding must produce Noren-to-Zellij PTY bytes matching
the same pinned artifact and fixture in a direct-host control; an accepted
Noren action records deliberate consumption separately. At the inner boundary,
Zellij-to-child bytes and consumed Zellij actions must match the v0.44.3 oracle,
not necessarily the outer bytes. Evidence records the host and inner keyboard
protocols plus application-cursor and newline modes. Only explicitly neutral,
legacy-only literal-key cases may use simple byte equality; every other case
preserves the two boundaries.

`codex-lab` owns the future executable compatibility evidence. `Claude Code`
additionally owns security review for clipboard/OSC handling and remote test
sanitization. These are evidence roles, not implementation assignments.

## Negotiation, layout, and IME unknowns

- Protocol names are not interchangeable. KKP, CSI-u, modifyOtherKeys, legacy
  xterm encodings, application-cursor mode, and terminfo aliases need
  byte-for-byte fixtures. `$TERM` or a terminal brand string is never proof of
  a negotiated capability.
- KKP support in v0.44.3 is deliberately a subset. Noren must not advertise
  flags, event types, push/pop semantics, or key distinctions it cannot
  preserve through the pinned Zellij path.
- Noren panes/tabs and Zellij panes/tabs are different layout layers. Tests must
  record both trees, chrome offsets, cell dimensions, focus, and ownership;
  visual similarity alone is insufficient.
- `Alt`, `Meta`, macOS Option, Super/Command, dead keys, ANSI/JIS/ISO physical
  layouts, and XKB mappings are not aliases. The effective input source and raw
  bytes belong in every keyboard evidence bundle.
- IME preedit, candidate UI, and committed PTY bytes are separate. A screenshot
  can verify candidate placement but cannot prove byte preservation; the raw
  helper proves committed bytes but cannot prove native UI placement.
- SSH can segment escape sequences and delay resize/query replies. Remote
  success cannot be inferred from a local run, and Zellij HTTPS remote attach is
  outside the SSH-host fixture unless separately scoped.
- Default and Unlock-First results apply only to the hashed v0.44.3 fixtures.
  Custom KDL, plugins, modes, and later releases require separate evidence.

## Security, legal, and trademark boundary

Noren must bound OSC and paste payloads, keep clipboard writes permissioned,
avoid recording clipboard contents or agent/session secrets, and keep a child
failure from crashing the local UI. OSC 52 is especially sensitive: upstream
source behavior is descriptive evidence, not permission for Noren to read or
write a user's clipboard silently.

Zellij is named nominatively as the compatibility target. Noren is not
affiliated with or endorsed by the Zellij project and must not copy Zellij
logos, screenshots, site assets, or marks. No Zellij code or assets were copied
